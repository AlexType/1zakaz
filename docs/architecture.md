# Предлагаемая архитектура

Статус: рабочее предложение, не приказ создавать инфраструктуру.

## Компоненты

- Один монорепозиторий для Next.js/React/TypeScript, ASP.NET Core API, общей документации и инфраструктурных конфигураций, когда будет разрешено писать код.
- Next.js App Router обслуживает публичные страницы с серверным рендерингом и интерфейс сотрудников. Интерактивный код загружается там, где нужен. Next.js не становится вторым источником бизнес-правил и не обращается напрямую к PostgreSQL.
- Один ASP.NET Core API как модульное приложение. Предполагаемые области: контент и SEO, модели, отдельные автомобили/кейсы, расчёты, заявки, медиа, сотрудники/права и настройки. Границы уточняются по рабочим сценариям. Контракт API описывается в OpenAPI; клиентские типы синхронизируются с ним.
- PostgreSQL — структурированные записи, связи, состояния, журнал изменений и параметры расчётов. S3 Timeweb — оригиналы и производные изображений. В БД хранятся ссылки и метаданные файлов.
- Авторизация сотрудников, разграничение ролей, проверка загрузок, резервные копии и восстановление входят в проект, а не добавляются после запуска.

## Данные для калькуляторов

Для каждого параметра администратор выбирает режим `ручной` либо `автоматический`, если для него есть проверенный источник. Автоматическое значение показывает источник и время обновления; перед сохранением ручного переопределения сотрудник видит итог расчёта. Нужно заранее решить, сохраняется ли последнее корректное значение при недоступности источника, когда оно считается устаревшим и кто подтверждает изменение формулы. Для каждой страны могут быть разные правила; обещать точную цену без согласованной методики нельзя.

## Окружения и поставка

- Локально: Next.js запускается непосредственно на Mac; API, PostgreSQL и S3-совместимый сервис — через Docker Compose. Для локальной разработки используются вымышленные персональные данные.
- Тестовое окружение: отдельный сервер, база и бакет в российской локации. Уведомления и интеграции настраиваются так, чтобы тестовые заявки не уходили реальным клиентам.
- Продакшен: отдельный от старого Bitrix сервер под Next.js и API в Docker Compose, управляемый PostgreSQL Timeweb и S3 Timeweb. База без публичного доступа, если приложение подключено через приватную сеть. Размещение всех компонентов, резервных копий и логов с персональными данными в РФ проверяется отдельно.
- GitHub Actions: проверки PR; сборка версии; автоматическая выкладка в тестовое окружение после слияния; продакшен — из зафиксированной версии с отдельным запуском и проверкой. Миграции БД, резервная копия и возможность отката входят в процедуру выпуска. Детальный механизм будет выбран после создания окружений.

GitHub может хранить исходный код и выполнять сборку, но персональные данные клиентов и производственные секреты не должны попадать в репозиторий, артефакты или логи CI. Соответствие 152-ФЗ требует анализа всей обработки заявок, включая почту, CRM, аналитику и внешние API, а не только выбора российского хостинга.

## Правила поддерживаемости

Для фронтенда используем рекомендации FSD для Next.js: маршруты `app` отдельно от слоёв `_pages`, `widgets`, `features`, `entities`, `shared`. Не создаём срез ради одного файла; не выносим весь код страницы в виджеты искусственно. На backend — разделение по предметным областям и короткие сценарии внутри них, с проверками критичных правил расчёта и публикации. Архитектурные решения фиксируются вместе с причиной и последствиями.
