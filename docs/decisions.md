# Решения и вопросы

## Согласовано владельцем проекта

1. Новый продукт заменяет оба действующих сайта целиком: основной Bitrix-сайт и отдельный сайт `avto`.
2. Первый запуск выполняется после реализации полного согласованного функционала; жёсткого срока на быстрый MVP нет.
3. Исходный код фронтенда и backend будет в одном монорепозитории. Сейчас в репозитории только документация и инструкции агентам.
4. Рабочий стек: Next.js/React/TypeScript, ASP.NET Core, PostgreSQL, S3 Timeweb, Docker Compose, GitHub Actions. Изменение стека возможно по аргументированной причине до начала реализации.
5. Разработка: Next.js на Mac напрямую, остальные локальные сервисы в контейнерах; отдельное тестовое окружение Timeweb до выпуска.
6. По интервью с заказчиком от 22.09.2026 клиентские личные кабинеты для первого запуска не требуются. Административные учётные записи сотрудников — отдельная необходимость.

## Требуют согласования перед реализацией

1. Доменная схема после замены: остаются ли два сайта/поддомена, какие разделы объединяются и что происходит со всеми существующими URL.
2. Точный набор типов контента, поля и связи. В частности, нужны ли отдельные записи для конкретных автомобилей, модельных страниц, клиентских кейсов и автомобилей в наличии; какие статусы и переходы используются.
3. Для каждого калькулятора: формула, источники данных, допустимая свежесть автоматических значений, ручное переопределение, округление, отображение неопределённости и ответственный за проверку.
4. Как сотрудники реально обрабатывают заявки: источники, роли, назначение, этапы, напоминания, каналы связи, существующая CRM, отчёты. Спроектировать минимальное количество действий для типовых задач и проверить прототип с менеджерами.
5. Перечень старых страниц, контента и данных для миграции; нужна ли история лидов; требования к сохранению поисковых позиций и аналитики.
6. Дизайн и контент: фирменный стиль, тексты, фотографии, мобильные сценарии, языки, ответственность за наполнение.
7. Политика персональных данных: юридический оператор, формы согласия, сроки хранения, разрешённые интеграции и расположение почты, логов и резервных копий.
8. Требования к доступности и мониторингу с учётом ранее наблюдавшихся сетевых сбоев у части пользователей.
9. Каким курсом реально оплачиваются автомобили: официальный ЦБ, курс банка/поставщика с надбавкой или утверждённый внутренний курс; кто задаёт надбавку и когда цена становится окончательной.
10. Есть ли действующие договоры и право переноса данных AJES или других каталогов, а также договоры с перевозчиками, которые предоставляют подходящие для автомобилей API.
11. Какие автомобили компания размещает вручную: в наличии, на заказ, уже купленные клиентам; нужен ли отдельно живой каталог сторонних аукционных лотов после замены Bitrix и на каких договорных условиях.
12. Как рассчитывается и публикуется цена конкретной машины: исходная валюта, курс, надбавка/коэффициент, расходы, срок действия, ручная фиксация; какие изменения должны проходить подтверждение.

## Предложение по работе с заявками для обсуждения

Вместо сложной CRM по умолчанию начать с одной рабочей очереди: новая заявка сразу видна, похожие заявки связаны, есть ответственный, следующий шаг и срок, короткая история контактов и фильтры «мои / без владельца / требуют действия». Менеджер должен за несколько секунд открыть контекст: страницу или расчёт, с которого пришёл клиент. Уведомления должны вести в эту очередь, а не становиться единственным местом хранения заявки. Какие каналы и автоматизации нужны на самом деле, решается с теми, кто будет ежедневно обрабатывать лиды.
